# SightFlash（五线速读）设计文档

- 日期：2026-09-05
- 状态：已获用户批准（2026-09-05）
- 项目代号：`sightflash`（工作名「五线速读」，名字可随时更换）

## 1. 背景与目标

用户为零基础～半入门乐理水平：认识 do re mi、能看简谱，但无法把五线谱上的音符位置快速对应到音名 / 琴键。

**核心目标**：把「五线谱位置 ↔ 音名 C~B ↔ 钢琴琴键」的映射练成条件反射，用**速度（每分钟正确认/弹音数）** 与 **准确率** 量化进步。

**成功标准（MVP 达成后）**：
- 在真琴/电子琴上，看高/低音谱单音能稳定弹出对应键，常用音域准确率 ≥ 90%
- 达到 ≥ 40 音/分钟 的识别速度（可作为后续目标，不硬性做进 MVP 门槛）
- 用户形成每日短练习惯（连续打卡）

## 2. 产品形态

**手机网页版（PWA）**：浏览器直接使用，可"添加到主屏幕"当 App 用，支持离线。目标运行环境为安卓 Chrome（移动优先）。

> 说明：用户电脑无 Android/Java/Flutter 工具链，网页方案零安装、迭代最快；未来可打包 APK。此形态已与用户确认。

## 3. 命名与语言

- 界面语言：简体中文
- 认音命名体系：**音名 C~B**（固定音高，不与可动唱名冲突），按钮固定 7 个。
- 工作名 SightFlash（五线速读）。

## 4. 两种练习模式

共享同一套**出题引擎**，仅"答题方式"不同：

| | 🎹 跟弹模式（主角） | 👆 认音模式（备用） |
|---|---|---|
| 场景 | 在电子琴/电钢琴旁（声音需外放，不能戴耳机） | 无琴时练纯认读 |
| 答题 | 看谱 → 真琴弹 → 麦克风判定 | 看谱 → 点 C~B 按钮 |
| 能力 | 谱→手指 真视奏 | 谱→音名 纯认读 |

## 5. 核心训练循环（两模式共用框架）

```
出题：大五线谱显示一个空心全音符（含所在线/间，超五线显示加线）
 ↓
答题（跟弹：弹真琴由 App 听音判定 / 认音：点按钮）
 ↓
对 → 变绿 + 该音钢琴音，自动下一音（认音可用琴键或音名作答，见 §20）
错 → 红闪 + 显示正确答案 + 播你实际作答的错音；跟弹模式额外显示"你实际弹的音名（偏高/偏低）"
 ↓
每轮 60 秒倒计时（可调 30s）
 ↓
结算页：弹(认)对数 / 速度(音/分) / 准确率 / 错音清单 / 阶段进度
```

**按键布局**：7 个音名按钮固定位置（防位置记忆作弊）。认音作答另含**仿真钢琴键盘**入口（2026-09-06 增补，见 §20）。跟弹模式按钮仍显示音名用于提示。

## 6. 出题逻辑

- 从**当前阶段解锁的音符池**随机抽样。
- **错音池加权**：错过的音权重更高，直至连续多次正确才出池。
- 避免连续出现同一音。
- 随机数需**可注入种子**（便于单测复现）。
- 升阶门槛：任一完整轮次 **准确率 ≥ 85%** 即解锁下一阶段。

## 7. 谱号与难度阶梯

- 谱号选择：**高音谱号 / 低音谱号 / 混合**（训练开始时选）。
- 低音谱从 S2 解锁，混合模式从 S3 解锁。

高低音池统一**以中央 C（C4）为锚点**向两侧展开（这正好让用户看到同一个 C4 在高、低音谱里的不同位置）：

| 阶段 | 高音谱池 | 低音谱池 | 门槛 |
|------|---------|---------|------|
| S1 | C4·D4·E4 | —（未解锁） | 任一完整轮次准确率 ≥85% |
| S2 | C4~G4（5 音） | C4·B3·A3（3 音） | 同上 |
| S3 | C4~B4（7 音） | C4~F3（5 音）；解锁混合模式 | 同上 |
| S4+ | 向上扩至 C5·D5… | 向下扩至 E3·D3·C3… | 同上 |

- **默认目标音域**：高音 C4~G5、低音 G2~C4（含加线），覆盖双手常用区间。
- 上述具体音集为**默认参数**，真实试用后可微调——属可调参数而非占位。
- **全局阶段制**：阶段进度跨谱号共享（用任意谱号达到门槛即升阶）；某谱号/混合模式未解锁时，开始界面对应选项置灰。

## 8. 音频判定管线（跟弹模式核心）

```
① 麦克风授权 + 校准：弹任意音确认"听得到、识别准"（校准失败给引导提示）
② 实时监听（Web Audio API + getUserMedia）
③ 起音检测（onset）：能量跳变 + 稳定音高窗口，过滤噪声/误触发
④ 音高识别：YIN / McLeod PSM 轻量算法（MVP）；预留 CREPE（onnxruntime-web）升级口
⑤ 比对：识别音名 vs 目标音名。允许 ±30 音分容差；**八度必须一致**
⑥ 反馈 → 结算
```

**判错兜底**：
- 弹错 → 显示实际弹的音名及与目标差多少（如 "你弹了 G4，偏高一个全音"）
- 卡住 → 「看答案」逐级提示：谱号+音名 → 键位图，尽量逼自己先读
- 检测到嘈杂/多音/不清晰 → 该题不计成绩并重出

## 9. 激励系统

- **每日打卡**：今日目标（弹对 100 音 或 5 分钟），达成点亮；连续天数 streak。
- **结算反馈**：本轮成绩 + 阶段进度条；刷新纪录标识。
- 等级随阶段推进展示。

## 10. 数据与统计

- 存储：浏览器本地 **IndexedDB**，无需账号，离线可用。
- 记录字段：日期、模式、谱号、阶段、正确数/总数、速度(音/分)、准确率。
- 展示：速度趋势、准确率趋势、错音分布（哪个音总错）。
- **隐私：麦克风音频仅实时处理，绝不录制、绝不上传。**
- 设计数据抽象（`storage/repo`），未来可平滑加云同步而不改 UI。

## 11. 技术选型

- **Vite + React + TypeScript**；PWA 用 `vite-plugin-pwa`（manifest + Service Worker，可离线安装）
- 样式：CSS Modules（设计 token，移动优先）
- 图表：自绘轻量 SVG（仅 2~3 个趋势小图，不引图表库）
- 状态：React Context + hooks，不引路由库（单页多视图切换）
- 持久化：IndexedDB（`idb` 小封装）
- 音频检测模块化：`PitchDetector` 接口 + YIN 实现，CREPE 未来以同接口替换

核心逻辑（`core`）为**纯 TS、无框架**，与 UI 完全解耦，可独立单测。

├─ src/

│  │  ├─ generator/             出题引擎：阶段定义、音符池、加权抽样、计时计分、升阶判定
│  │  ├─ audio/                 PitchDetector 接口、YIN 实现、onset 起音检测、

## 13. UI 视图

1. **首页**：今日打卡状态、连续天数、今日目标进度、快捷开始、查看数据
2. **开始设置**：选模式（跟弹/认音）→ 选谱号（高/低/混合）→ 跟弹先做麦克风校准 → 开始
3. **练习视图**：五线谱目标音 + 倒计时 + 反馈区 + 音名按钮行 + 仿真钢琴键盘（认音作答；跟弹模式按钮为提示，无屏幕键盘）
4. **结算视图**：成绩数字 + 错音清单 + 升阶进度 + 打卡点亮 + 返回
5. **数据视图**：趋势图 + 错音分布
6. **设置**：提示音开关、倒计时时长(30/60s)、清除本地数据

## 14. 错误处理与边界

- **无/拒绝麦克风权限**：引导开启；认音模式不受影响
- **听不到音**：校准环节给出音量/距离引导，超时提示
- **环境噪声/多音**：onset 误触发重出该题，不计成绩
- **识别结果八度错误**：判错并提示实际音名（帮助校准），计入错音池
- **耳机弹琴**：提示需外放
- **浏览器不支持 Web Audio/getUserMedia**：降级提示 + 认音模式仍可用

## 20. 增补：琴键作答 + 钢琴音色（2026-09-06 试用反馈，已批准）

用户试用认音模式后提出两条升级，均落在**认音（tap）模式**内：① 除 7 个音名按钮，还要能直接点**仿真钢琴键盘**作答；② 答题声音由单音"叮"改为**匹配音高的钢琴音**。本增补在认音范围内取代 §5/§13/§17 中「认音=仅按钮、提示音」的旧表述。

### 20.1 双作答入口（同屏共存）
- 同一题可用音名按钮（按音级判，任意八度对，原逻辑不变）或钢琴琴键（**精确到八度**判）作答，两入口均计入成绩。
- 会话新增纯函数 `answerKey(sess, midi)`：`midi === target.midi` 判对；对则推进下一题，错则停题可重试（与 `answerTap` 同构）。
- 钢琴琴键窗口随当前题谱号固定：**高音窗 C4~C6、低音窗 G2~G4**（覆盖目标 高 C4~G5 / 低 G2~C4；混合模式随题切换）。黑白键齐全仿真布局，**琴键不标字母**（靠黑键相对位置找音，正是要练的能力）；点黑键恒为错（池内无变化音）。
- 练习屏布局（手机竖屏自上而下）：谱面 → 反馈区 → 音名按钮行 → 钢琴键盘；谱面随可用高度缩放。

### 20.2 钢琴音色（替换 ok/bad 提示音）
- 引擎模块 `piano.ts`：WebAudio **加法合成**——按需生成每音 AudioBuffer（基频 + 若干泛音、轻微不谐性、按音区指数衰减），播放带短包络；离线可用、无素材依赖、预留替换真采样的播放接口。jsdom/无 WebAudio 或设置关闭时静默不抛。
- 播放规则（受设置 `settings.sound` 开关控制）：
  - 按下琴键 → 立即播该键音（即使它不对，先听见自己弹了什么）
  - 判对 → 播目标音（琴键作答按下已播，无需重播）
  - 判错 → 播用户实际作答的**错音**：琴键作答即该键音；音名按钮作答播「所选音名 @ 谱面音符的八度」（目标 C4 选 D → 播 D4），让用户听出"这不是谱上那个音"
  - **不播正确答案音**（避免靠听音反推答案）
- 视觉反馈（绿/红闪 + 显示正确音名）维持不变。

### 20.3 与里程碑 B（真琴跟弹）的关系
- 屏幕琴键作答是"谱 → 琴键位置"训练，可作为里程碑 B「真琴 + 麦克风判定」（§8）**上琴前的过渡练习**；两者共用出题引擎、错音池与统计，跟弹模式原设计不变，麦克风管线仍属里程碑 B。

### 20.4 范围与边界
- 只改认音模式作答与发声；统计、打卡、存储结构不变（history 仍按 `expectedMidi` 登记错音）。设置页「提示音」开关沿用并管辖钢琴音。旧 `sound.ts` 的 ok/bad 单音提示被替换移除。

## 21. 增补：键盘横屏优先 + 三音区 + 中央C 参照（2026-09-06 二轮试用反馈，已批准）
> 本条取代 §20.1 的琴键窗口尺寸与屏幕方向约定（其余作答/发声规则不变）。

### 21.1 横屏优先（手机）
- PWA manifest 增加 `orientation: 'landscape'`：Android 安装为 standalone 后自动横屏；iOS 无程序级强制旋转，靠用户在浏览器内旋转（Safari 不遵循 manifest orientation）。
- **自适应**：`orientation: landscape` 媒体查询下，`#root` 内容宽度上限由 640px 放宽到约 920px，练习屏钢琴键盘随之横贯可用宽度、高度增至约 180px（保证 3 音区时白键仍可手按）；**竖屏**下布局不变（640 上限、键盘较窄），但练习屏顶部显示「建议横屏」提示条（横屏时 CSS 隐藏）。
- 提示条**可点击**：点击优先请求全屏（Chrome/Android 全屏通常自动转横）并尝试 `orientation.lock('landscape')` 锁定；浏览器不支持程序转屏（如 iOS Safari 无根元素全屏/无 orientation）时，提示条文案原地变为「请手动旋转手机 ↻」，保证点击始终有反馈。

### 21.2 琴键窗口：随谱号 3 个八度（取代 §20.1 的 2 八度）
- 高音题窗口 **C3~C6**（midi 48–84）、低音题窗口 **C2~C5**（midi 36–72）；各 22 白键 / 15 黑键，仍随当前题谱号切换（混合模式随题跳），仍完整覆盖出题区（高 C4~G5 / 低 G2~C4）。
- 扩出的音区仅为可弹范围，不作为出题目标；判定与发声规则同 §20.2（点到扩出键 = 播该键音并按错处理，可重试）。

### 21.3 中央C 参照
- 键盘不标字母（§20.1 原则不变），仅在**中央C（C4=60）白键底部加一枚琥珀色圆点**作唯一参照标记（data-testid `c4-marker`）；高音/低音窗口均含 C4，故两窗口都显示。

## 22. 增补：横屏紧凑版式——一屏放全、不纵向滚动（2026-09-06 三轮试用反馈，已批准）
> 真机横屏后「上下间距过大、需上下滚动才能看全」。本条在 §21.1 基础上新增：练习屏在横屏下**高度固定为视口高、纵向不滚动**；取代 §21.1 中「钢琴高度固定增至约 180px」与默认纵向可滚动的表述（其余横屏约定不变：谱号随题 3 八度窗、中央 C 圆点、竖屏布局原样）。

### 22.1 版式：练习屏一屏放全（100dvh flex 自适应，纯 CSS）
- 采用**纯 CSS** 收敛纵向空间（不改 `StaffView` 几何/音符绘制——高音区符干向上可达很高，裁切 svg 有削干风险，故不做 viewBox 裁剪）。
- 横屏媒体查询内，练习屏设为 `height:100dvh; overflow:hidden` 的 **flex 竖排**，自上而下：表头行 → 谱面 → 反馈区 → 音名按钮行 → 钢琴键盘。
- 纵向空白收敛，**可调参数**（真机微调优先改这四处）：`.practice` 竖向内边距压到 ~4px（横向 ~12px）、行间隙 ~2px；反馈区 `min-height` 降到 18、去 margin；音名按钮横屏由正方形改**矮胶囊**（高 ~32、`max-width` 仍 ~64、字号 1.1rem）；**谱面靠 `.staff-wrap` 限宽 180**（svg 272/320 纵横比 → 纵高 ≈153）。
- **钢琴键盘自适应**：`flex:1 1 0` 吸收剩余高度，`min-height:108`（矮屏兜底）＋ `max-height:46dvh`（高屏封顶）。
  - 换算（固定部分 ≈ 255，按真实行高）：约 360px 高视口键盘触 108 兜底线仍完整可见、375px ≈ 120、430px ≈ 175——**常见横屏高度均无需纵向滚动**。
- 实现注意：`StaffView` 的 svg 带内联 `max-width:320`（样式表压不过内联样式），故谱面宽度须约束在**父容器 `.staff-wrap`** 上而非 svg 本身；svg `width:100%` 随父缩放，均匀缩放不削符号。
- 谱号、音符、出题逻辑一律不动；竖屏布局与样式完全不变。

### 22.2 测试与验收
- 纯 CSS 版式无法在 jsdom 单测断言（无真实布局引擎）；回归靠 vitest 全量绿 + `npx tsc -b` 通过 + `vite build` 成功。
- 真机验收（README 手动清单新增一项）：Android 安装 PWA 横屏 & iOS Safari 手动横屏下，练习屏**整屏可见、无纵向滚动**；键盘高度随屏高自适应（矮屏不压垮、高屏不过长）。**验收须含一台视口高 ≈360px 的横屏设备**（最紧预算档），确认钢琴键盘完整可见可点、不被裁剪。若真机略有出入，按 22.1「可调参数」就地微调。
